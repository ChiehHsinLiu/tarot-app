# Design

## Context

- The tarot pictures today: 38 hand-written SVGs in `src/assets/tarot/` (majors and courts), generated by `scripts/tarot-art/` (`npm run draw:tarot`) and loaded by `src/lib/tarot-art.ts` with an eager `import.meta.glob`. The 40 number cards are drawn in code from `pips.ts`. `CardFace.tsx` picks between the two. Every drawing passes `art-format.ts` (an allow-list of elements, attributes and `art-*` colour classes, a 3 KB cap, and at least one `art-ink` shape).
- The deck choice exists only in dev: `DeckPicker.tsx` with `DeckId = 'tarot' | 'lenormand'`, held in `ComposingState.deck` (`tarot-state.ts`). `Composer` and `TarotScreens` build Lenormand behind `import.meta.env.DEV` so it folds out of the public bundle.
- A `Reading` is `{ spreadId, question, cards }`. It feeds the reading view, the share link (`share.ts`) and the Copy for Claude prompt.
- Shared links are decoded in `App.tsx` (`decodeReading`) and shown by `TarotScreens` as a face-up `ReadingView`.

## Goals / Non-Goals

**Goals:**
- One switch, the card style, threads from the composer through the reading, the reveal and share links, without touching card data or the prompt.
- 78 consistent, recognisable dachshund drawings that stay small and safe to inline.
- The owner reviews and approves every drawing before anything ships.

**Non-Goals:**
- Remembering the deck choice across visits (it resets with the screen, as the spread does).
- A dachshund card back, or dachshund art for the oracle or Lenormand.
- Any change to the Classic drawings or `pips.ts`.

## Decisions

### Style lives beside the reading, not inside it
Add a `TarotStyle = 'classic' | 'dachshund'` type. `DeckId` becomes `'classic' | 'dachshund' | 'lenormand'`, and the `'tarot'` id is renamed `'classic'`. The revealed state becomes `{ kind: 'revealed'; reading; style }`, and `decodeReading` returns `{ kind: 'reading'; reading; style }`. `Reading` itself is unchanged, so `prompt.ts`, `draw.ts` and the Lenormand code don't move, and the prompt is identical for both styles by construction.
*Alternative:* a `style` field on `Reading`. It's simpler to pass around, but every Reading consumer (the prompt, Lenormand, tests) would see a field that means nothing to it.

### The picture is chosen in one place
`CardFace` takes a `style` prop. For `dachshund` it inlines `DACHSHUND_ART[card.id]` for all 78 cards (no pips). For `classic` it keeps today's logic. `ReadingView` passes the style to every `CardFace`. The flip, mat and preview code are unchanged because the back is shared.

### Art pipeline mirrors the Classic one
- `scripts/dachshund-art/` holds `shapes.ts` (the root, plus a **parametric dachshund helper**: one body, head, ears, tail and legs drawn from position, scale, facing and a few poses such as stand, sit, sleep, beg and run), `majors.ts`, `courts.ts`, `numbers.ts` (each scene places N suit symbols plus one or more dachshunds), and `draw.ts` → `src/assets/dachshund/<card-id>.svg`. A new `npm run draw:dachshund` script runs it.
- Reusing one dog helper keeps all 78 cards looking like the same breed and the same hand, and keeps each file small.
- `src/lib/dachshund-art.ts` loads them with an eager glob, like `tarot-art.ts`.
- **Colour (owner asked for "more colorful" after batch 0):** the Dachshund deck adds eight fixed scene classes, `art-coat`, `art-ear`, `art-sun`, `art-sky`, `art-leaf`, `art-water`, `art-rose` and `art-plum`, styled in `styles/card.css` with the same colours in both palettes (faces stay cream). Dogs are brown everywhere. The suit's family colour stays on the frame, the suit symbols and the outlines, so suits stay distinct.
- `art-format.ts` gains a `dachshundProblems` check: the same allow-list plus those eight classes, with a **5 KB** cap, because three dogs, or a Ten with ten symbols plus a dog, need more room than 3 KB. A new `dachshund-art.test.ts` checks exactly 78 files, one per card id, the format, and no duplicates.
- The suit-symbol shapes in `CardFace.tsx`'s `SYMBOLS` are redrawn as SVG path data in `scripts/dachshund-art/shapes.ts`, so the number cards use recognisably the same cups, wands, swords and pentacles.

### Bundled with the tarot screen
The drawings are in the same lazily loaded tarot chunk as the Classic art, so "no network after the screen has shown" holds with no prefetch logic. The estimate is about 78 × 2.5–3 KB ≈ 220 KB raw, roughly 50 KB compressed, and the home page's first load is untouched (site-deployment "Each screen loads its own content").
*Alternative:* a separate chunk loaded when Dachshund is picked. It's smaller for Classic users, but it adds a loading state and an offline gap. That's not worth it at this size.

### Share link carries `d=dachshund`
`encodeReading(reading, { includeQuestion, style })` adds `d=dachshund` before `q`. `decodeReading` reads the query with `URLSearchParams`: a missing `d` means Classic, `dachshund` means Dachshund, and anything else is invalid. Links stay `v1`, so every existing link decodes exactly as before.

### Public picker, dev extras
`DECK_OPTIONS` lists Classic and Dachshund always, and Lenormand only when `import.meta.env.DEV` (inline, so it folds away). The existing production-bundle check for Lenormand text stays and is extended to assert the picker shows exactly two options in the public e2e.

### Review in batches with contact sheets
A dev-only script writes `contact-sheet.html` to the scratchpad. It shows the batch's cards at mat size and at 320 px, in the light and dark palettes, and upright and reversed. The owner approves each batch before the next is drawn.
- **Batch 0:** a style sample of The Fool, Three of Cups and Queen of Cups, to settle the dog's look first.
- **Batch 1:** majors 0–10. **Batch 2:** majors 11–21. **Batch 3:** the 16 courts. **Batch 4:** Ace to Ten of Wands and Cups. **Batch 5:** Ace to Ten of Swords and Pentacles.
- Batch 0's three cards are redrawn in their own batches if the approved style moves on.
- Wiring lands early behind a fallback (a missing dachshund drawing shows the Classic picture) so batches can be seen in the real app. The coverage test and the fallback's removal come last.

## Risks / Trade-offs

- [78 drawings is a lot of work, and the style could drift between batches] → One shared dog helper, batch 0 sets the look, and every contact sheet shows previous approved cards beside the new ones.
- [Counting symbols on a busy scene at 320 px] → Number-card scenes keep symbols large and separate from the dog. The contact sheet includes a 320 px row, and the owner checks counts there.
- [The tarot chunk grows by about 50 KB compressed] → Acceptable for a screen-level chunk. Checked against the build output in the final task.
- [Renaming the `'tarot'` deck id] → It's internal only (state and the dev picker), and no link or storage uses it.
- [Traditional symbols in dog scenes might read as copying a published deck] → Compositions are original, as with the Classic deck. Only traditional motifs are reused, never another deck's layout.

## Migration Plan

Ship as one push once all 78 drawings are approved and the unit and e2e checks pass. Old share links are unaffected. Rollback is a revert: Dachshund links would then show "This reading link isn't valid." (`d` would be unknown), which is acceptable.
